# FAQs Component, FAQ Page & Admin Management — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a backend-managed FAQ block (title + accordion, max 6) to the landing, contact, and about pages, plus an all-FAQs page at `/faqs`, with full admin CRUD.

**Architecture:** Laravel 10 serves a Blade admin CRUD and a small JSON endpoint (`GET /api/faqs`). Vue 3 components (`FaqsSection.vue`, `FaqsPage.vue`) consume that endpoint and are mounted through the existing `client.layout.app` layout. All pages share one ordered FAQ pool; inactive FAQs are never exposed publicly.

**Tech Stack:** PHP 8.2 / Laravel 10, MySQL (runtime) and SQLite in-memory (tests), Vue 3 `<script setup>`, Vite 4, existing CSS tokens in `resources/css/app.css`.

**Spec:** `docs/superpowers/specs/2026-11-13-faqs-design.md`

## Global Constraints

- PHP `^8.1`, Laravel `^10.0`, Vue `^3.2`, Vite `^4.5` — do not add npm or Composer dependencies.
- Use `--royal-yellow`, `--charcoal`, `--slate-steel`, `--white` CSS variables; global `border-radius: 0`.
- Do not change `resources/views/client/layout/app.blade.php` head tags or add the unused `title`/`meta_*` yields.
- Public FAQ data: only `is_active = true`, ordered by `sort_order ASC, id ASC`.
- `GET /api/faqs` accepts `limit` as an integer from 1 to 50; invalid values return 422.
- Admin FAQ routes require `auth` and `verified` middleware; `GET /faqs` is public.
- Answers are plain text rendered with `{{ }}` interpolation and `white-space: pre-line` — never `v-html`.
- FAQ admin CRUD uses the existing Blade pattern: `admin.admin_master`, cards, `session('message')` + `session('alert-type')`, toastr, and delete confirmation.
- Runtime database is MySQL `meksis`, which is not running in this environment. Tests use SQLite `:memory:`; manual verification uses a temporary SQLite file.
- Git repository has a Windows ownership quirk. Prefix git commands with
  `git -c safe.directory='D:/Laravel Projects/Meksis' ...`.
- Do not stage or commit unrelated existing changes (`storage/logs/laravel.log`, pre-existing `public/build` changes).

## Review Focus

1. An empty or fully inactive FAQ table must hide the titled block on the three pages, and `/faqs` must show a short empty message instead of a blank page.
2. Inactive FAQs must never appear in `/api/faqs`; `limit` outside 1–50 or non-numeric must return 422, not 500.
3. A missing `faq_settings` row must not break `/api/faqs`, the shared section, or the admin settings screen — defaults come from `FaqSetting::current()`.
4. Answers containing HTML or script tags must render as literal text (interpolation, not `v-html`).
5. Long questions and answers must wrap inside the accordion on mobile, and `/faqs` must show one heading (hero), not a duplicated section title.

namespace App\Http\Controllers\Api;

            'subtitle' => $settings->subtitle,
            'faqs' => $query->get(['id', 'question', 'answer']),
        ]);
    }
}

Replace `app/Http/Controllers/BackOffice/FaqController.php` with:

```php
<?php

namespace App\Http\Controllers\BackOffice;

use App\Http\Controllers\Controller;
use App\Models\BackOffice\Faq;
use App\Models\BackOffice\FaqSetting;
use Illuminate\Http\Request;

class FaqController extends Controller
{
    public function FaqPage()
    {
        return view('client.faqs');
    }

    public function EditSettings()
    {
        $settings = FaqSetting::current();

        return view('admin.backOffice.faq.edit_faq_settings', compact('settings'));
    }

    public function UpdateSettings(Request $request)
    {
        $request->validate([
            'title' => 'required|string|max:255',
            'subtitle' => 'nullable|string|max:255',
        ]);

        FaqSetting::current()->update([
            'title' => $request->title,
            'subtitle' => $request->subtitle,
        ]);

        return redirect()->back()->with([
            'message' => 'FAQ settings have been updated successfully',
            'alert-type' => 'success',
        ]);
    }

    public function AddFaq()
    {
        $nextOrder = (int) Faq::max('sort_order') + 1;

        return view('admin.backOffice.faq.add_faq', compact('nextOrder'));
    }

    public function StoreFaq(Request $request)
    {
        $validated = $this->validateFaq($request);

        $validated['sort_order'] = $request->filled('sort_order')
            ? (int) $request->sort_order
            : ((int) Faq::max('sort_order') + 1);
        $validated['is_active'] = $request->boolean('is_active');

        Faq::create($validated);

        return redirect()->route('faq.index')->with([
            'message' => 'FAQ has been added successfully',
            'alert-type' => 'success',
        ]);
    }

    public function IndexOfFaqs()
    {
        $faqs = Faq::query()->ordered()->get();

        return view('admin.backOffice.faq.index_faq', compact('faqs'));
    }

    public function EditFaq($id)
    {
        $faq = Faq::findOrFail($id);

        return view('admin.backOffice.faq.edit_faq', compact('faq'));
    }

    public function UpdateFaq(Request $request)
    {
        $validated = $this->validateFaq($request);

        $validated['sort_order'] = $request->filled('sort_order')
            ? (int) $request->sort_order
            : 0;
        $validated['is_active'] = $request->boolean('is_active');

        Faq::findOrFail($request->id)->update($validated);

        return redirect()->route('faq.index')->with([
            'message' => 'FAQ has been updated successfully',
            'alert-type' => 'success',
        ]);
    }

    public function DeleteFaq($id)
    {
        Faq::findOrFail($id)->delete();

        return redirect()->back()->with([
            'message' => 'FAQ has been deleted successfully',
            'alert-type' => 'success',
        ]);
    }

    private function validateFaq(Request $request): array
    {
        return $request->validate([
            'question' => 'required|string|max:255',
            'answer' => 'required|string',
            'sort_order' => 'nullable|integer|min:0',
        ]);
    }
}
```

Note: `UpdateFaq` uses `$request->id` (not validated) to find the record, matching the existing admin controllers' style. `is_active` is false whenever the checkbox is absent, which is the intended "deactivate" behaviour.
